# Отключение компонентов кластера для проведения нагрузочного тестирования локально.

## Этап тестирования 1.

### Spring cloud

Для проведения локального нагрузочного тестирования оставляем только приложение
сервиса и postgres в docker. Т.к. в pom.xml есть зависимости spring-cloud и
config-server, то при старте приложения они пытаются найти параметры
подключения, отключается это вот так:

```yaml
spring:
  cloud:
    config:
      enabled: false
      import-check:
        enabled: false

```

### Kafka

Поскольку в проекте есть зависимость spring-kafka, Spring Boot автоматически
пытается настроить продюсер и консьюмер при запуске.

```yaml
 kafka:
   listener:
     auto-startup: false # Не запускать @KafkaListener при старте
   admin:
     auto-create: false  # Не пытаться создавать топики и проверять кластер при старте
```

Как это сработает: Spring создаст реальный KafkaTemplate и спокойно внедрит его
в ваш TaskEventProducer. Приложение запустится без ошибок, но пока вы явно не
вызовете метод отправки сообщения в Kafka, оно не будет обращаться к сети.
