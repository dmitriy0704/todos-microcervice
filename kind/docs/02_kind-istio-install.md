## **1. Ты не ошибся с label**

Ты выполнил:

```
kubectl label namespace default istio-injection=enabled
```

А потом:

```
istioctl install --set profile=default --set tag=default -y
```

Это допустимо.

Что здесь происходит:

- `istio-injection=enabled` — метка, которая говорит Istio автоматически
  внедрять Envoy sidecar в новые Pod'ы пространства имён `default`.
- `istioctl install` — устанавливает компоненты Istio в кластер, в первую
  очередь управляющий компонент `istiod`.
- После установки Istio Kubernetes сможет автоматически добавлять Envoy в Pod'ы
  при их создании.

То есть порядок этих двух команд не принципиален. Сам label не запускает
установку Istio и не должен ей мешать.

**Важный момент:** Pod'ы, которые ты создал до установки Istio, автоматически не
получат sidecar. Их нужно будет пересоздать после успешной установки Istio.

## **2. Не будем пока ничего удалять и переустанавливать**

Сначала выясним, что именно зависло. Возможно, Istio уже частично установился, а
`istioctl` просто ждёт готовности какого-то компонента.

Выполни следующие команды по очереди.

**Шаг 1. Проверим, к какому кластеру подключён kubectl:**

```
kubectl config current-context
```

Для kind ожидаем что-то вроде:

```
kind-kind
```

**Шаг 2. Проверим состояние кластера:**

```
kubectl get nodes -o wide
```

Нода должна иметь статус `Ready`.

**Шаг 3. Посмотрим, что произошло с Istio:**

```
kubectl get pods -n istio-system -o wide
```

Если namespace существует, увидим установленные Pod'ы. Если нет — получим
сообщение, что namespace не найден.

**Шаг 4. Проверим остальные компоненты:**

```
kubectl get pods -A
```

Нас интересуют не только Istio, но и твои `tasks-service`, `postgres`,
`config-server`.

**Шаг 5. Посмотрим, что говорит сама утилита:**

```
istioctl version
```

Она покажет версию клиента и, если управляющий компонент уже запущен, его
версию.

## **3. Как в итоге должна выглядеть установка**

Для твоего учебного проекта я бы пока использовал самый простой вариант —
профиль `default`, без дополнительных настроек.

Официальная документация Istio рекомендует именно такой вариант для базовой
установки.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://istio.io\&sz=32)

Istio+1

После успешной установки последовательность будет примерно такой:

1. **Установка Istio**

   `istioctl install --set profile=default -y`
2. **Проверка управляющего компонента**

   `kubectl get pods -n istio-system`
3. **Включение автоматического внедрения sidecar**

   `kubectl label namespace default istio-injection=enabled`
4. **Пересоздание приложений**

   Чтобы существующие Pod'ы получили Envoy sidecar.
5. **Проверка**

   `kubectl get pods -n default`

### **Что я рекомендую сделать дальше**

Не торопись сразу изучать VirtualService, DestinationRule и Gateway. Сначала
убедимся, что понимаешь работу sidecar.

Выполни:

```
kubectl describe pod <имя-pod> -n default
```

Посмотри секцию `Containers`. Там должны быть `tasks-service` и `istio-proxy`.

Затем:

```
istioctl proxy-status
```

Эта команда покажет, подключился ли Envoy к управляющему компоненту Istio
(`istiod`).

**Следующий логичный этап обучения:** разобраться, как Istio перехватывает
сетевой трафик между микросервисами, а затем попробовать настроить
`VirtualService` и `DestinationRule`.
